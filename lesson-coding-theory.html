Coding Theory — Error-Correcting Codes

Coding theory designs efficient and error-resistant ways to transmit digital information. It spans linear codes (Hamming, Golay), algebraic codes (Reed-Solomon, BCH), cyclic codes, convolutional codes, turbo codes, LDPC (low-density parity-check), polar codes, and capacity-approaching codes. The subject sits at the intersection of information theory, algebra, and combinatorics — enabling everything from CDs and QR codes to deep-space communication.

"Coding theory is the art of adding redundancy to data so that errors can be detected and corrected — making noisy channels reliable."
— Claude Shannon / Richard Hamming
Part 1

🔤 Linear Codes — The Algebra of Error Correction

Repetition
Linear Codes, Generator Matrices, and Hamming Codes
A linear [n,k] code over GF(q) is a k-dimensional subspace of GF(q)ⁿ. The generator matrix G (k×n) maps messages to codewords: c = mG. The parity-check matrix H ((n−k)×n) satisfies Hcᵀ = 0 for codewords. The Hamming distance d(c₁,c₂) is the number of positions where they differ. The minimum distance d of a code determines its error-correction capability: t = ⌊(d−1)/2⌋ errors can be corrected. The Singleton bound: d ≤ n−k+1. Codes achieving this are MDS (maximum distance separable). The Hamming code [2^r−1, 2^r−r−1, 3] corrects 1 error per block. The binary [7,4,3] Hamming code has 16 codewords. The Golay code [23,12,7] corrects 3 errors — used by Voyager. The weight enumerator W(x,y) = Σ A_i x^{n−i} y^i counts codewords by weight. MacWilliams identity relates weight enumerators of a code and its dual.
Linear codes transform error correction into linear algebra — parity checks detect where errors occur, and the minimum distance tells you how many you can fix.
Part 2

🌀 Algebraic Codes — Reed-Solomon and BCH

Polynomials
Reed-Solomon Codes — Polynomial Evaluation and Berlekamp-Massey
Reed-Solomon (RS) codes evaluate polynomials over GF(q). For message (m₀,...,m_{k−1}), form polynomial p(X) = m₀ + m₁X + ... + m_{k−1}X^{k−1}, then codeword c = (p(α₁),...,p(α_n)) for distinct evaluation points α_i. RS codes are MDS: [n,k] with d = n−k+1. The Berlekamp-Massey algorithm efficiently decodes RS codes by finding the error locator polynomial from syndromes. BCH codes (Bose-Chaudhuri-Hocquenghem) are cyclic codes with designed minimum distance using roots in extension fields. A BCH code with designed distance δ has α, α², ..., α^{δ−1} as roots of the generator polynomial. The Peterson-Gorenstein-Zierler algorithm solves the key equation for BCH decoding. RS codes are a special case of BCH codes (n = q−1). RS codes are used in CDs, DVDs, QR codes, and satellite communication. The [255,223,33] RS code is used by NASA — it corrects 16 byte errors per block.
Reed-Solomon codes use polynomial evaluation over finite fields — the elegant algebra makes them both powerful and efficiently decodable.
Part 3

🔄 Convolutional Codes and Turbo Codes

Memory
Convolutional Codes, Viterbi Algorithm, and Turbo Codes
Convolutional codes process a sliding window of input bits through a finite state machine. The encoder has memory m; the constraint length K = m+1. The trellis diagram represents all possible state transitions. The Viterbi algorithm (1967) finds the most likely transmitted sequence by dynamic programming on the trellis — it's the maximum-likelihood decoder for convolutional codes. The free distance d_free determines performance. Convolutional codes are often combined with puncturing to adjust the rate. Turbo codes (Berrou, 1993) consist of two parallel convolutional encoders separated by an interleaver, decoded iteratively by exchanging extrinsic information — they approach the Shannon limit (< 1 dB away). The BCJR algorithm (Bahl-Cocke-Jelinek-Raviv) computes MAP symbol probabilities for turbo decoding. Turbo codes revolutionized coding — they're used in 3G/4G cellular, satellite, and deep-space communication.
Turbo codes achieved near-Shannon-limit performance by iteratively exchanging soft information between two decoders — a breakthrough that changed communications.
Part 4

⚡ LDPC Codes, Polar Codes, and Capacity-Achieving Codes

Sparse
LDPC, Polar Codes, and Modern Iterative Decoding
LDPC codes (Gallager, 1963; rediscovered 1990s) are linear codes with a sparse parity-check matrix H. The Tanner graph is a bipartite graph with variable nodes and check nodes. The iterative belief propagation (BP) decoder (sum-product algorithm) passes messages along edges: variable nodes send likelihood estimates to check nodes, check nodes enforce parity constraints. LDPC codes achieve capacity on the binary erasure channel and approach it on AWGN — they're used in 5G, Wi-Fi, DVB-S2, and 10GBASE-T. Irregular LDPC codes with optimized degree distributions perform even better. Polar codes (Arikan, 2009) are the first provably capacity-achieving codes for symmetric channels. They use channel polarization: by recursively combining and splitting channels, some become perfectly reliable and others completely noisy. Information is sent on the reliable bits (frozen bits are fixed). Successive cancellation decoding (SC) is the basic decoder; SC-list (SCL) decoding improves performance. Polar codes are used in 5G control channels. The noisy-channel coding theorem (Shannon) provides the fundamental limit: the capacity C = max I(X;Y) bits per channel use.
LDPC codes with iterative decoding approach Shannon's limit; polar codes provably achieve it — the sixty-year quest to reach capacity is essentially complete.

Finite Field Construction and Arithmetic for Code Design

All algebraic error‑correcting codes operate over a finite field GF(q) where q = p^m for a prime p and integer m ≥ 1. The prime field GF(p) consists of the integers {0,1,…,p−1} with addition and multiplication modulo p. Extension fields GF(p^m) are built by selecting an irreducible polynomial f(X) of degree m over GF(p) and forming the quotient ring GF(p)[X]/⟨f(X)⟩. Elements are represented as polynomials of degree < m with coefficients in GF(p); addition is coefficient‑wise modulo p, while multiplication is polynomial multiplication followed by reduction modulo f(X). The choice of f(X) influences the field’s primitive element α, which generates the multiplicative group GF(q)* of order q−1. A primitive element satisfies αq−1=1 and α^k≠1 for 0<k<q−1. In practice, tables of primitive polynomials for small m are used; for example, over GF(2) the polynomial X<sup>4+X+1 is primitive and yields GF(16) with α a root of that polynomial. Arithmetic in GF(2^m) is especially efficient in hardware because addition is XOR and multiplication can be implemented with shift‑register circuits (linear feedback shift registers). For Reed‑Solomon codes the evaluation points are usually the successive powers of a primitive element α, i.e. α0, α1, …, αn−1 with n = q−1. The generator polynomial of a narrow‑sense BCH code of designed distance δ is the least common multiple of the minimal polynomials of α, α2, …, αδ−1. Minimal polynomials are obtained by taking the product of (X−αi·p^j) over all conjugates under the Frobenius map. Understanding how to compute minimal polynomials, how to perform Euclidean division in GF(q)[X], and how to derive the error‑locator polynomial from syndromes are core skills for implementing algebraic decoders. Software libraries often pre‑compute logarithm and antilogarithm tables to turn multiplication into addition of exponents modulo q−1, which speeds up syndrome calculation and polynomial arithmetic dramatically.

Weight Enumerators, MacWilliams Identities, and Distance Spectra

The weight enumerator of a linear [n,k] code C is the bivariate polynomial W_C(x,y)=∑i=0^n A_i xn−i y^i where A_i counts codewords of Hamming weight i. The dual code C^⊥ has weight enumerator WC^⊥(x,y)=∑i=0^n B_i xn−i y^i. The MacWilliams identity states that WC^⊥(x,y)=|C|-1 W_C(x+y, x−y). This relation allows the weight distribution of a code to be derived from that of its dual, which is often easier to compute because the dual may have smaller dimension. For the binary [7,4,3] Hamming code, the weight enumerator is W(x,y)=x7+7x4y3+7x3y4+y7. Applying the identity yields the dual [7,3,4] simplex code weight enumerator W^⊥(x,y)=x7+7x3y4. The distance spectrum {A_i} directly determines the probability of undetected error on a binary symmetric channel with crossover probability p: P_ue = ∑i=1^n A_i p^i (1−p)n−i. For soft‑decision decoding, the complete weight enumerator (CWE) generalises the concept by tracking the composition of symbols from a larger alphabet, enabling exact performance analysis of codes over non‑binary channels. The MacWilliams transform extends to CWEs, providing a powerful tool for evaluating the performance of concatenated schemes where the inner code’s CWE is transformed by the outer code’s weight enumerator. In practice, enumerators for long codes are rarely computed exhaustively; instead, the first few non‑zero coefficients (the minimum distance and the number of minimum‑weight codewords) dominate the error floor, and bounding techniques such as the Delsarte linear programming bound use the MacWilliams identities to obtain upper limits on A_i without full enumeration.

Worked Example: MacWilliams Identity for a [7,4,3] Hamming Code
Given the weight enumerator W_C(x,y)=x7+7x4y3+7x3y4+y7 of the binary [7,4,3] Hamming code, compute the weight enumerator of its dual code C^⊥ using the MacWilliams identity.
The dual code has dimension n−k = 3, so |C| = 24 = 16. The MacWilliams identity for binary codes is WC^⊥(x,y)=|C|-1 W_C(x+y, x−y). Substitute x→x+y, y→x−y in W_C: (x+y)7 + 7(x+y)4(x−y)3 + 7(x+y)3(x−y)4 + (x−y)7. Expand using binomial theorem and collect terms. Because the code is self‑orthogonal only up to the dual, many cross terms cancel. The result simplifies to (1/16)[16x7 + 112x3y4] = x7 + 7x3y4. Hence the dual [7,3,4] simplex code has weight enumerator WC^⊥(x,y)=x7+7x3y4, confirming that all non‑zero codewords have weight 4.
Exam Strategy: Recognising Dual Code Parameters
When a question provides the weight enumerator of a code and asks for the minimum distance of the dual, apply the MacWilliams identity symbolically rather than expanding fully. Identify the smallest i>0 for which the coefficient of xn−iy^i in the transformed polynomial is non‑zero; that i is the dual minimum distance. Memorise the weight enumerators of the Hamming, simplex, and Golay codes because they appear frequently in dual‑code problems.

Syndrome Decoding, Euclidean Algorithm, and Berlekamp–Massey Detailed Steps

For a linear [n,k] code with parity‑check matrix H, the syndrome of a received vector r is s = H r^T. If the error vector e has weight ≤ t = ⌊(d−1)/2⌋, the syndrome uniquely determines e. In algebraic codes the syndrome components are evaluations of the error‑locator polynomial Λ(X) at the known roots of the generator polynomial. For a BCH or Reed‑Solomon code with designed distance δ, the first δ−1 syndromes S1,…,Sδ−1 are computed as S_j = r(α^j) for j=1,…,δ−1. The key equation Λ(X) S(X) ≡ Ω(X) (mod Xδ−1) relates the error‑locator polynomial Λ(X) and the error‑evaluator polynomial Ω(X), where S(X)=∑j=1δ−1 S_j Xj−1. The extended Euclidean algorithm applied to the pair (Xδ−1, S(X)) yields polynomials (Λ, Ω) satisfying the key equation with deg Λ ≤ t and deg Ω < deg Λ. The algorithm proceeds by repeated polynomial division: at each step compute quotient Q and remainder R such that A = Q B + R, then update (A,B)←(B,R) and track the co‑factors that express the current remainder as a combination of the original pair. When the degree of the remainder falls below t, the corresponding co‑factor is the error‑locator polynomial. The Berlekamp–Massey algorithm is an iterative reformulation that avoids explicit polynomial division by maintaining a discrepancy Δ and updating Λ and an auxiliary polynomial B. Initialise Λ=1, B=1, L=0, m=−1. For each syndrome index n from 0 to δ−2 compute Δ = Sn+1 + ∑i=1^L Λ_i Sn+1−i. If Δ=0, increment the iteration counter; otherwise set T=Λ, Λ = Λ − Δ Xn−m B, and if 2L ≤ n then L = n+1−L, B = T, m = n. After processing all syndromes, Λ(X) is the error‑locator polynomial. Its roots are found by Chien search (evaluating Λ(α−i) for i=0,…,n−1). The error values are then obtained from Ω(α−i) / Λ'(α−i) using Forney’s formula. Both algorithms run in O(t2) field operations and are the standard decoders for RS and BCH codes in practice.

Concatenated Codes, Product Codes, and Interleaving Strategies

Concatenated coding combines an outer code C_out over a large alphabet GF(q^m) with an inner code C_in over a smaller alphabet GF(q). The outer encoder maps k_out symbols from GF(q^m) to n_out symbols; each outer symbol is then represented as an m‑tuple over GF(q) and encoded by the inner encoder into n_in symbols. The overall block length is n = n_out n_in and the rate is R = R_out R_in. Forney’s construction (1966) showed that choosing C_out as a Reed‑Solomon code and C_in as a maximum‑likelihood decodable code (e.g., a short convolutional code with Viterbi decoding) yields an overall error probability that decays exponentially with block length while keeping decoding complexity polynomial. Product codes are a special case where both component codes are linear block codes and the codeword array is formed by encoding rows with C_row and columns with C_col. The resulting code has parameters [n_row n_col, k_row k_col, d_row d_col]. Iterative row‑column decoding (also called turbo product decoding) passes soft information between the two component decoders, achieving performance close to the Shannon limit for moderate block sizes. Interleaving is essential to break burst errors into random‑like errors that the component codes can handle. A block interleaver writes symbols row‑wise into a matrix of size L×M and reads them column‑wise, spreading a burst of length B over at most ⌈B/M⌉ symbols per codeword. Convolutional interleavers use shift registers with increasing delays to achieve the same effect with lower latency. In modern standards (e.g., DVB‑S2, 5G NR), a combination of LDPC outer codes, BCH inner codes, and bit‑level interleavers is employed to combat both random and burst errors while supporting hybrid automatic repeat request (HARQ) with incremental redundancy.

Polar Code Construction: Bhattacharyya Parameters and Successive Cancellation List Decoding

Polar codes achieve the symmetric capacity of any binary‑input discrete memoryless channel by channel polarization. Starting from N independent copies of the channel W, the polar transform G_N = B_N F⊗n (where F = [[1,0],[1,1]] and B_N is a bit‑reversal permutation) synthesises N virtual channels W_N(i). As N→∞, the fraction of virtual channels with capacity near 1 approaches the symmetric capacity I(W), while the rest have capacity near 0. The reliability of each synthetic channel is quantified by its Bhattacharyya parameter Z(W_N(i)) = ∑_y √{W_N(i)(y|0) W_N(i)(y|1)}. For the binary erasure channel Z equals the erasure probability; for the binary symmetric channel Z = 2√{p(1−p)}. The recursive relations Z(W^−) ≤ 2Z(W) − Z(W)2 and Z(W+) = Z(W)2 allow efficient computation of all Z values for a given N. The construction selects the K indices with smallest Z as information bits; the remaining N−K indices are frozen to known values (usually zero). Encoding is simply u G_N where u contains information and frozen bits. Successive cancellation (SC) decoding estimates bits sequentially: for i=1..N, if i is frozen set û_i=0; otherwise compute the log‑likelihood ratio L_i = log (W_N(i)(y, û1…ûi−1|0) / W_N(i)(y, û1…ûi−1|1)) and decide û_i = 0 if L_i≥0 else 1. SC decoding has complexity O(N log N) but suffers a performance gap at finite lengths. SC‑list (SCL) decoding maintains a list of the L most likely partial paths, extending each path with both 0 and 1 for information bits and pruning to the L best according to path metrics. A cyclic redundancy check (CRC) concatenated with the polar code (CA‑polar) enables selection of the correct codeword from the final list, closing the gap to maximum‑likelihood performance. In 5G NR control channels, a CA‑polar code with N=512, K=56, and list size L=8 is standard, delivering block error rates below 10−3 at signal‑to‑noise ratios within 0.5 dB of the Shannon limit.

  • Confusing the primitive polynomial with the generator polynomial of a BCH code; the former defines the field, the latter defines the code.
  • Assuming the MacWilliams identity holds for non‑linear codes; it is valid only for linear codes and their duals.
  • Neglecting the degree condition deg Ω < deg Λ when applying the Euclidean algorithm, which leads to an incorrect error‑locator polynomial.
  • Treating product codes as simple concatenations without accounting for the iterative exchange of soft information between row and column decoders.
  • Using the Bhattacharyya parameter of the original channel directly for polar code construction instead of the recursively computed values for each synthetic channel.
  • Forgetting that the frozen bits in a polar code must be known to both encoder and decoder; any mismatch causes catastrophic decoding failure.
