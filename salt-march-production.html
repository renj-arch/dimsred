02 / MOTION
Transitions are cuts with intent

The edit has a grammar.

The grammar is paper-ledger. The signature moves are listed below. Transition counts come from the final edit manifest.

document reveal: the page moves before the camera doespage-turn wipe: a printed edge carries the next set instamp match: a rubber stamp lands where the last shot cutruling lines: horizontal rules become the horizon of the next set
2

Page turn

A page turns and the next set arrives on its back.

2

Paper wipe

A printed edge carries the next set into frame.

2

Iris

A lamp or valve closes to a circle, moving the eye to the next object.

1

Dip

A held gap between two arguments.

75

Hard cut

The default join. Used where softening would weaken the argument.

05 / PIPELINE
Free CI, no paid keys

Every frame is assembled on GitHub.

Blender, Piper, Chromium and ffmpeg run on a free Ubuntu CPU runner. The owner's machine writes the code; it does not render the film. The pipeline is public, repeatable and allowed to fail loudly.

01

Source lock

The storyboard is a JSON contract. Every narration line names a source. The validator refuses unsourced lines, missing shots and filler before a runner is allowed to render.

release: film-salt-march-final-38 · timeline.json + metadata.json
02

Procedural sets

Blender 4.2 builds the film's sets as still plates. No stock images.

scripts/film/render-plates.js
03

Narration

Piper reads the script locally with en_US-lessac-medium. No cloud narration, no per-word billing, no API key in the repository.

scripts/film/build-film.js
04

Camera and type

Chromium drives the timeline frame by frame: push-ins, pans, match cuts, mask wipes, impact cards and captions. The camera is code, so every frame is repeatable.

js/film.js
05

Score and master

ffmpeg synthesises the score, mixes the narration, burns the SRT into the master and encodes the MP4.

scripts/film/build-film.js
