What is Inequality?

Inequality questions in banking exams test your ability to compare quantities using mathematical inequality symbols and coded relationships. Given a set of statements with inequalities, you must determine which conclusions definitely follow. These are quick-scoring questions that appear regularly in prelims.

Basic Symbols

1. Greater Than (>): A > B means A is greater than B.

2. Less Than (<): A < B means A is less than B.

3. Equal To (=): A = B means A equals B.

4. Greater Than or Equal To (≥): A ≥ B means A is greater than or equal to B.

5. Less Than or Equal To (≤): A ≤ B means A is less than or equal to B.

Coded Inequalities

In banking exams, symbols are often replaced with codes (e.g., @, #, $, %, &). A key is provided showing what each symbol means. For example: P @ Q means P > Q, P # Q means P < Q, P $ Q means P = Q, P % Q means P ≥ Q, P & Q means P ≤ Q. You then use these coded relationships to evaluate conclusions.

Rules for Combining Inequalities

1. Transitive Property: If A > B and B > C, then A > C. Similarly for <, ≥, ≤.

2. Combining ≥ and >: If A ≥ B and B > C, then A > C (the ≥ gets 'absorbed' by >).

3. Combining > and ≥: If A > B and B ≥ C, then A > C.

4. Combining ≤ and <: If A ≤ B and B < C, then A < C.

5. Combining < and ≤: If A < B and B ≤ C, then A < C.

6. Non-Transitive Cases: If A > B and B < C, NO relationship between A and C can be determined. Similarly for A ≥ B and B ≤ C, or A > B and B = C and C < D, etc.

Solved Examples

Example 1 (Direct Inequality)
Statements: P > Q ≥ R < S = T ≤ U
Conclusions: I. P > R II. T < S

Options: a) Only I follows b) Only II follows c) Both follow d) Neither follows
Solution: a) Only I follows. I. P > Q ≥ R → P > R ✓ (transitive property). II. T ≤ U and S = T, so T = S. The conclusion says T < S which is false. Therefore only I follows.
Example 2 (Coded Inequality)
Key: A @ B means A > B; A # B means A < B; A $ B means A = B; A % B means A ≥ B; A & B means A ≤ B.
Statements: M @ N # P $ Q % R
Conclusions: I. M @ Q II. N & R

a) Only I follows b) Only II follows c) Both follow d) Neither follows
Solution: d) Neither follows. Convert statements: M > N < P = Q ≥ R. I. M @ Q means M > Q. From M > N and N < P = Q, M and Q cannot be compared because M > N and N < Q → M could be >, <, or = Q. II. N & R means N ≤ R. From N < P = Q ≥ R, we have N < Q ≥ R. N could be ≤ or > R. So neither conclusion follows.
Example 3 (Chain of Inequalities)
Statements: A ≥ B > C = D ≤ E < F
Conclusions: I. A > D II. C < F III. B ≤ E

a) Only I follows b) Only I and II follow c) Only II and III follow d) All follow
Solution: b) Only I and II follow. I. A ≥ B > C = D → A > D ✓. II. C = D ≤ E < F → C < F ✓. III. B > C = D ≤ E → B > D ≤ E, so B could be >, =, or < E. No definite relationship. So only I and II follow.

Shortcut Techniques

  • When combining inequalities, always chain them in one direction. Convert ≤ and ≥ to consistent direction before combining.
  • If two variables have opposite inequality signs between them (e.g., A > B < C), no relationship can be determined.
  • For coded inequalities, first convert all coded statements into symbols using the key, then evaluate.
  • In 'either-or' cases, check if the two conclusions cover all possibilities for the relationship.
Pro Tip
In prelims, 3-5 inequality questions appear. They are among the fastest to solve — each can be done in 15-20 seconds once you master the transitive and non-transitive rules. Always check the 'either-or' condition carefully as it is a common trap.

Transitive and Non‑Transitive Chains in Mixed Signs

When a chain contains only strict signs (> or <) or only non‑strict signs (≥ or ≤), the transitive property holds without exception: A > B > C implies A > C, and A ≥ B ≥ C implies A ≥ C. The difficulty appears when the chain mixes strict and non‑strict symbols, for example A > B ≥ C or A ≥ B > C. In the first case the overall relation between A and C is strict because the presence of a single strict link forces the whole chain to be strict: A > C. In the second case the chain is also strict: A ≥ B > C yields A > C. However, a chain such as A ≥ B ≤ C is non‑transitive; no definite relation between A and C can be deduced because the direction of the inequalities reverses. The examiner often builds statements like P ≥ Q > R ≤ S and asks whether P > S follows. The correct approach is to split the chain at the reversal point, treat each monotonic segment separately, and then check whether the two segments can be linked through a common variable. If the common variable appears with opposite senses (once as a lower bound, once as an upper bound), the conclusion is indeterminate unless an additional statement fixes the variable’s exact value.

A practical rule: write the chain in a single direction by converting every ≤ to ≥ (or vice‑versa) and reversing the order of the variables. For A ≥ B ≤ C rewrite as B ≤ A and B ≤ C. Now both statements give an upper bound for B; they do not relate A and C. This technique eliminates the visual trap of “mixed signs” and makes the transitive test mechanical. Remember that equality (=) behaves as both ≤ and ≥ simultaneously, so a chain containing A = B ≥ C can be reduced to A ≥ C (strictness depends on the other link). Mastery of this conversion is the single biggest time‑saver in high‑difficulty inequality sets.

Either‑Or and Neither‑Nor Conclusions

Examiners frequently frame two conclusions that are mutually exclusive but collectively exhaustive, for example “I. X > Y II. X ≤ Y”. Only one of them can be true for any concrete assignment, yet the logical structure of the statements may leave the relation between X and Y undetermined. In such a case the correct answer is “Either I or II follows”. The decision rule is: derive the strongest possible relation from the given statements; if that relation is a strict inequality (or a strict equality) then the corresponding conclusion follows and the opposite does not. If the strongest relation is a non‑strict inequality (≤ or ≥) then both the strict and the non‑strict versions are possible, so the either‑or pair is triggered. A third pattern is the “neither‑nor” pair where both conclusions are false under every admissible assignment; this occurs when the statements force a relation that contradicts both conclusions, e.g., statements give X > Y while conclusions are X < Y and X = Y.

To evaluate an either‑or pair quickly, construct the tightest bound for each variable using the chain‑combining rules. Then test each conclusion against that bound. If exactly one conclusion is compatible with the bound, that conclusion follows. If both are compatible (which can happen only when the bound is non‑strict), the answer is “Either I or II follows”. If none is compatible, the answer is “Neither I nor II follows”. A common pitfall is to treat “≥” as “>” when checking the strict conclusion; always keep the distinction because a single equality case can flip the answer from “Only I follows” to “Either I or II follows”.

Either‑Or Evaluation
Statements: A ≥ B > C = D ≤ E. Conclusions: I. A > D II. A ≤ D. Choose the correct option.
Combine the chain: A ≥ B > C = D gives A > D (strict because B > C). The second part D ≤ E does not affect the relation between A and D. The strongest derived relation is A > D. Conclusion I matches this strict relation, so I follows. Conclusion II (A ≤ D) contradicts the derived strict relation, therefore II does not follow. Since only one conclusion follows, the answer is “Only I follows”.
Exam‑Day Shortcut
When you see an either‑or pair, first write the combined chain in one direction. Identify the tightest bound for the two variables involved. If the bound is strict, the matching strict conclusion is the sole follower. If the bound is non‑strict, mark “Either I or II follows” without further calculation. This eliminates the need to test both conclusions separately.

Inequalities with Variables on Both Sides

Standard textbook problems place all variables on the left and constants on the right, but competitive exams often present statements such as 2X + 3 ≥ 5Y – 1 or P – Q > R + S. The presence of variables on both sides does not change the logical engine; it only requires an algebraic rearrangement before the transitive rules can be applied. The first step is to isolate each variable on a separate side of the inequality, preserving the direction of the sign. For 2X + 3 ≥ 5Y – 1, subtract 5Y and 3 from both sides to obtain 2X – 5Y ≥ –4. This is now a linear inequality in two variables. If a second statement provides another linear relation, e.g., X – Y ≤ 2, the two can be combined by eliminating one variable (multiply the second by 2 and subtract) to derive a bound on the remaining variable. The elimination method mirrors solving simultaneous equations, but the inequality sign must be tracked carefully: multiplying by a negative number reverses the sign.

When the statements are purely relational (no numeric coefficients), treat each variable as a node in a directed graph where an edge A → B means A > B (or ≥). Variables on both sides simply create edges in both directions, e.g., P – Q > R yields P > Q + R, which can be split into P > Q and P > R only if Q and R are known to be non‑negative. In the absence of sign information, the safe approach is to keep the compound inequality intact and use it as a single constraint during chain combination. The examiner’s favourite trap is to give A + B > C and C > D and then ask whether A > D follows. Without knowing the sign of B, the conclusion is indeterminate; the correct answer is “Neither follows”. Always check for hidden sign assumptions before splitting compound inequalities.

Application of Inequalities in Data Sufficiency

Data sufficiency questions embed inequality statements inside a “statement‑1 / statement‑2” framework. The task is to decide whether each statement alone, or both together, provide enough information to answer a target inequality such as “Is X > Y?”. The solving template is identical to the chain‑combination method, but the decision points are different. First, translate each statement into a set of relational edges. Then, for each statement individually, attempt to derive a definite relation between the target variables. If a single statement yields a strict or non‑strict bound that answers the question, that statement is sufficient. If not, combine the edges from both statements and test again. The crucial nuance is that a statement may be sufficient even when it does not give a direct comparison; for example, “X ≥ 5” and “Y ≤ 4” together imply X > Y, but each alone is insufficient. The examiner often includes a statement that gives a range (e.g., 3 ≤ X ≤ 7) and another that gives a point value (Y = 5). The combination may still be insufficient if the ranges overlap.

A systematic approach: draw a number line for each variable based on the information in the statements. Mark the known bounds. The question “Is X > Y?” is answered “Yes” only if the minimum possible value of X exceeds the maximum possible value of Y. It is answered “No” only if the maximum possible X is ≤ the minimum possible Y. Any overlap means the data are insufficient. This visual method eliminates algebraic errors and works equally well for coded inequalities once the code is decoded. Practice converting each statement into a pair of bounds (lower, upper) for every variable; then the sufficiency test becomes a simple interval comparison.

Complex Coded Inequalities with Multiple Symbol Sets

Advanced papers sometimes present two or three independent coding keys in the same question, for instance: “@ means >, # means <, $ means ≥” for the first set, and “% means ≤, & means =, * means ≠” for the second set. The statements then mix symbols from both sets, e.g., “A @ B # C $ D % E”. The first step is to build a master translation table that maps every symbol to its standard relation. Write the decoded chain in a single line, preserving the order of variables. Next, apply the chain‑combination rules exactly as for direct inequalities. Because the symbols are arbitrary, the examiner can hide a reversal of direction inside the code; for example, “#” might be defined as “<” in the first set but “>” in the second set. Always verify the key for each symbol before decoding; a single mis‑read symbol flips the entire chain.

When multiple keys exist, it is helpful to colour‑code or bracket the symbols belonging to each key while decoding. After translation, treat the resulting chain as a normal mixed‑sign chain. The presence of “≠” (not equal) introduces a non‑transitive element: from A ≠ B and B ≠ C no relation between A and C can be inferred. However, if a strict inequality also connects the same variables, the “≠” becomes redundant. The examiner may ask “Which of the following must be true?” and provide options that include “A ≠ C”. The correct answer is “Cannot be determined” unless a strict chain forces inequality. Practise decoding at least three different keys in a single sitting to build speed; the pattern recognition of symbol‑to‑relation mapping is the only skill that separates a 15‑second solution from a 60‑second one.

  • Assuming a mixed‑sign chain is transitive without checking for a reversal point.
  • Treating “≥” as “>” when evaluating an either‑or pair, missing the equality case.
  • Splitting a compound inequality with variables on both sides without confirming sign constraints.
  • Ignoring the interval‑overlap test in data‑sufficiency and declaring sufficiency prematurely.
  • Mis‑reading a coded symbol because two different keys are used in the same question.
  • Overlooking that “≠” provides no transitive information unless paired with a strict inequality.
  • Failing to convert all ≤ to ≥ (or vice‑versa) before chaining, leading to direction errors.

Inequalities with Conditional Operators

Conditional operators such as “if … then”, “only if”, and “unless” appear frequently in reasoning passages that embed inequality information. The logical structure of a conditional statement can be translated into a directed edge in the inequality graph, but the direction depends on the phrasing. “If A > B then C ≥ D” creates a dependency: the truth of the antecedent (A > B) guarantees the consequent (C ≥ D). In a chain‑combination exercise, this means the edge C ≥ D is *active* only when the antecedent can be proved from the given statements. The contrapositive “If C < D then A ≤ B” is logically equivalent and often more useful because it turns a forward implication into a backward restriction that can be combined with other known relations.

When multiple conditionals share variables, the examiner may ask which conclusions *must* hold regardless of whether the antecedents are satisfied. The safe approach is to treat each conditional as a pair of edges: one forward (antecedent → consequent) and one backward (negated consequent → negated antecedent). During chain building, only edges whose antecedents are already established in the current proof path may be traversed. This prevents the common error of chaining a consequent that rests on an unproven premise. A practical technique is to label each edge with a tag indicating its conditional status (e.g., “C1”, “C2”) and to propagate tags along the chain; a conclusion is unconditional only if its tag set is empty.

Another twist involves “only if” statements. “A > B only if C ≥ D” is logically “If A > B then C ≥ D”, identical to the simple conditional. “Unless” statements such as “A ≤ B unless C > D” translate to “If C ≤ D then A ≤ B”. Recognising these equivalences quickly is essential; a mis‑translation flips the inequality direction and corrupts the entire chain. Practice converting at least ten mixed conditional sentences into tagged edges before the exam; the pattern recognition reduces decoding time from 30 seconds to under 5 seconds per statement.

Multi‑Layered Chain Combination

Advanced questions often present three or more independent chains that intersect at shared variables. Each chain may use a different symbol set, and the intersection points can carry conflicting relations (e.g., Chain 1 gives X ≥ Y while Chain 2 gives X < Y). The resolution rule is strict: a variable pair can hold only the *strongest* relation that is logically forced by *all* chains simultaneously. If the chains are independent (no common variable), they remain separate and cannot be merged. When they share a variable, the combined graph is built by taking the union of edges and then applying the transitive closure *with conflict detection*.

Conflict detection works as follows: after constructing the union graph, run a depth‑first search from each node to compute the tightest lower and upper bounds reachable. If for any pair (U, V) the algorithm derives both U > V and U ≤ V, the data set is inconsistent and the question usually asks “Which of the following cannot be true?” or “The information is contradictory”. In consistent cases, the tightest bound (strict > overrides ≥, strict < overrides ≤) becomes the definitive relation for that pair. This method also handles “≠” edges: they only restrict equality and never create a directional bound unless paired with a strict inequality.

A practical shortcut for exam conditions is the “layer‑by‑layer” table. List all variables as rows and columns; fill each cell with the strongest relation known from any single chain. Then iteratively apply transitivity: if cell (A,B) shows ≥ and (B,C) shows >, update (A,C) to >. Repeat until no cell changes. Because the number of variables in reasoning sets rarely exceeds eight, the table fits on a single rough sheet and converges in two to three passes. This visual method eliminates the need to mentally track multiple symbol keys and makes conflicting relations immediately visible as opposing symbols in the same cell.

Worked Example: Multi‑Layered Chain
Statements (two symbol sets):
Set 1: @ means >, # means ≥, $ means <.
Set 2: % means ≤, & means ≠.
Given: A @ B, B # C, C $ D (Set 1).
Also: D % E, E & F (Set 2).
Question: Which of the following must be true?
1) A > D 2) B ≥ E 3) C ≠ F 4) A ≥ F
Step 1: Decode each statement.
Set 1: A > B, B ≥ C, C < D.
Set 2: D ≤ E, E ≠ F.
Step 2: Build union graph edges.
A > B ≥ C < D ≤ E, and E ≠ F.
Step 3: Apply transitivity where direction permits.
From A > B and B ≥ C ⇒ A > C.
From C < D and D ≤ E ⇒ C < E (strict because C < D and D ≤ E gives C < E).
From A > C and C < E ⇒ no direct relation between A and E (signs oppose).
From B ≥ C and C < E ⇒ no direct relation between B and E.
E ≠ F gives only non‑equality; no directional link to other variables.
Step 4: Evaluate options.
1) A > D? Chain A > B ≥ C < D gives A > C and C < D; cannot compare A and D ⇒ not must.
2) B ≥ E? B ≥ C < E ⇒ indeterminate ⇒ not must.
3) C ≠ F? C < E and E ≠ F ⇒ C could equal F (e.g., C=2, E=3, F=2) ⇒ not must.
4) A ≥ F? No path connects A to F ⇒ not must.
Answer: None of the above (option “None follows”).
Exam‑Day Strategy
When a question supplies two or more symbol keys, draw a quick key‑legend table in the margin (symbol → relation). Decode every statement into plain inequalities before attempting any chaining. Use the layer‑by‑layer matrix on rough paper; it turns a 3‑minute puzzle into a 45‑second scan. If a conflict appears, mark the contradictory cell and read the question stem — most “must be true” items become “cannot be true” once a conflict is spotted.

Inequalities in Logical Puzzles

Logical puzzles — seating arrangements, ranking ladders, grouping games — frequently embed inequality clues such as “P sits two places to the left of Q” or “R scores higher than S but lower than T”. These clues are essentially positional inequalities. The standard technique is to convert each clue into a numeric bound on a position index (1 … n) or a rank variable. For a linear row of eight seats, “P is two places left of Q” becomes pos(P) = pos(Q) – 2. “R scores higher than S” becomes rank(R) < rank(S) if rank 1 is the best. Once all clues are expressed as equations or inequalities over integer variables, the problem reduces to a constraint‑satisfaction task that can be solved by systematic elimination.

A powerful method is the “interval‑propagation” table. For each entity, maintain a lower bound (minimum possible position/rank) and an upper bound (maximum). Initialise all bounds to the full range (1 to n). Then iterate through the clues: a clue “X > Y” tightens lower(X) ≥ lower(Y) + 1 and upper(Y) ≤ upper(X) – 1. A clue “X = Y + k” sets both bounds simultaneously. After each pass, if any lower bound exceeds its upper bound, the puzzle is inconsistent (rare in well‑formed questions). The process converges quickly because each clue reduces the feasible interval for at least one variable. When the intervals collapse to singletons, the unique arrangement is found; otherwise, the remaining degrees of freedom correspond to the “cannot be determined” answer choices.

Examiners often combine inequality clues with “either‑or” statements (e.g., “Either A is immediately left of B or C is immediately right of D”). Treat each branch as a separate sub‑puzzle, solve both, and then intersect the solution sets. The intersection yields the statements that hold in *all* valid arrangements — exactly the “must be true” conclusions. Practising this bifurcation on paper with a simple branching diagram prevents the common mistake of mixing branches and deriving a false universal conclusion.

Weighted Comparison and Priority Rules

Some advanced sets assign a priority hierarchy to symbols, for example: @ > # > $ > % where “>” means “has higher priority than”. In such questions, a statement like “A @ B # C” does not translate to two independent relations; instead it means “A is related to B by @, and B is related to C by #, but the overall comparison between A and C follows the *highest priority* symbol present in the chain”. The rule: when chaining, the resultant relation between the endpoints takes the symbol with the highest priority among all symbols in the path. If the path contains both @ and #, the endpoint relation is @ (strict >). If the path contains only # and $, the endpoint relation is # (≥). This mimics the way programming languages evaluate overloaded operators.

To apply this, first decode each symbol to its base relation (>, ≥, <, ≤, ≠). Then, for every directed path between two variables, collect the set of base relations. The effective relation is the *strongest* in the sense of the priority order: strict > outranks ≥, which outranks ≠, which outranks ≤, which outranks <. Note that ≠ is non‑directional; it only matters when no directional relation exists. A practical algorithm: run a modified Floyd‑Warshall where the “distance” is a tuple (priority, direction). Initialise direct edges with their symbol’s priority. When relaxing an edge via an intermediate node, combine priorities by taking the maximum (highest priority) and propagate the direction of that highest‑priority edge. The final matrix gives the definitive relation for every pair.

Exam questions may ask “Which symbol represents the relation between X and Z?” after providing a chain with mixed symbols. The fastest solution is to scan the chain, note the highest‑priority symbol, and answer with that symbol — no full matrix needed. However, when multiple parallel chains exist between the same pair, you must compare the highest priority from each chain and then select the overall highest. This two‑level selection (within chain, then across chains) is the only place where a full matrix or a careful manual comparison is unavoidable.

Reverse Engineering Conclusions from Options

A time‑saving technique for “Which of the following must be true?” questions is to test each option against the given statements by attempting to construct a counter‑example. Because the variable domain is usually small (often implicit integers 1‑9 or simple orderings), a counter‑example can be built by assigning extreme values that satisfy all premises but violate the candidate conclusion. If a counter‑example exists, the option is *not* a must. If every attempt to violate the option forces a premise violation, the option is a must.

The procedure: (1) List all decoded premises as a set of inequalities. (2) For each option, temporarily add the negation of the option to the premise set. (3) Check consistency using the interval‑propagation method described earlier. If the augmented set is consistent, the option is not mandatory. If inconsistent, the option is mandatory. Because the number of options is typically four, this amounts to at most four quick consistency checks. In practice, the first two options often yield a counter‑example instantly, allowing you to eliminate them without full propagation.

An illustration: Premises: A > B, B ≥ C, C < D. Option: A ≥ D. Negate: A < D. Add to premises: A > B ≥ C < D and A < D. Assign numeric values: let D = 5, then A < 5 ⇒ A ≤ 4. Choose A = 4, B = 3, C = 2. All premises hold (4 > 3 ≥ 2 < 5) and A < D holds. Hence a counter‑example exists; A ≥ D is not a must. This reverse‑engineering approach turns a forward‑chaining problem into a series of tiny feasibility tests, each solvable in seconds.

  • Treating a conditional consequent as unconditional when its antecedent is not proven.
  • Merging independent chains without a shared variable, creating spurious transitive links.
  • Ignoring priority hierarchy and defaulting to the last symbol in a mixed‑symbol chain.
  • Assuming “≠” provides directional information when no strict inequality accompanies it.
  • Failing to bifurcate either‑or puzzle clues, leading to conclusions that hold only in one branch.
  • Overlooking the need to test the negation of each option when reverse‑engineering must‑be‑true conclusions.
  • Using a single interval bound for a variable that appears in multiple disconnected sub‑puzzles, causing cross‑contamination of constraints.

Mastering these advanced patterns converts the most time‑consuming inequality questions into routine checklist items.

Inequalities with Absolute Value and Modulus Expressions

Absolute‑value inequalities appear when a statement compares the distance of a variable from a reference point rather than its raw magnitude. The standard forms |x − a| < k, |x − a| ≤ k, |x − a| > k and |x − a| ≥ k translate directly into compound intervals: a − k < x < a + k, a − k ≤ x ≤ a + k, x < a − k or x > a + k, and x ≤ a − k or x ≥ a + k respectively. In reasoning questions the modulus is rarely written explicitly; instead the clue may read “the difference between P and Q is less than 3” or “R is at most 2 units away from 5”. The first step is to rewrite such verbal clues into the algebraic modulus form, then split into the two linear inequalities that define the feasible interval.

When several modulus clues involve the same variable, the feasible region becomes the intersection of the individual intervals. Because each interval is convex, the intersection is either a single continuous segment or empty. An empty intersection signals an inconsistent data set — a situation examiners use to create “cannot be determined” answer choices. A useful shortcut is to keep track of the tightest lower bound (maximum of all lower limits) and the tightest upper bound (minimum of all upper limits). If the lower bound exceeds the upper bound, the puzzle is contradictory.

Modulus clues can also be combined with ordinary directional inequalities. For example, “A > B” together with “|B − C| ≤ 2” yields a feasible band for C that slides along with the unknown value of B. The propagation technique is to first express the modulus as a pair of linear bounds on C in terms of B, then substitute the known range of B (derived from other clues) to obtain absolute numeric bounds for C. This two‑stage propagation — symbolic then numeric — is the core of solving mixed modulus‑direction sets.

Examiners often hide a modulus inside a coded symbol. A symbol such as “Δ” may be defined as “the absolute difference between the two variables is exactly 4”. Decoding the symbol first, then applying the interval‑intersection method, prevents the common error of treating the coded relation as a simple directional inequality. Remember that an exact‑difference modulus (|x − y| = k) produces two discrete possibilities (x = y + k or x = y − k) rather than a continuous interval; each branch must be explored separately, exactly as with an either‑or clue.

Finally, when the variable domain is restricted to integers (a frequent implicit assumption), the continuous interval collapses to a set of integer points. Counting these points can answer “how many values can X take?” questions without enumerating every combination. The count is simply ⌊upper⌋ − ⌈lower⌉ + 1 provided the interval is non‑empty.

Inequalities in Circular and Linear Seating Arrangements

Seating‑arrangement puzzles frequently embed inequality information to fix relative positions. In a linear row, a clue such as “P sits three places to the left of Q” translates to the index inequality pos(P) + 3 = pos(Q). When the clue is “P sits at least two places left of Q”, the relation becomes pos(P) + 2 ≤ pos(Q). The same principle applies to circular tables, but indices are taken modulo the number of seats. A statement “R is immediately right of S” on a circle of n seats means pos(R) ≡ pos(S) + 1 (mod n). Because modular arithmetic wraps around, a simple linear inequality is insufficient; the feasible set for a pair becomes a congruence class rather than an interval.

To handle modular inequalities, convert each positional clue into a congruence or a set of congruences. For “at most two seats apart” on a circle of eight, the condition is min(|pos(A) − pos(B)|, 8 − |pos(A) − pos(B)|) ≤ 2. This yields up to five admissible relative offsets (−2, −1, 0, 1, 2). When multiple such clues involve overlapping persons, the problem reduces to finding a common assignment of residues that satisfies all congruences and inequality bounds simultaneously. The Chinese Remainder Theorem is rarely needed because the modulus (number of seats) is the same for all clues; instead, a simple back‑tracking search over the small domain (typically ≤ 12 seats) is faster.

A powerful technique is to fix one person’s seat as a reference (say seat 1) and express every other person’s position as an offset from that reference. Each inequality then becomes a constraint on the offset variables. Because the reference can be rotated arbitrarily, the solution set is invariant under a global shift; fixing the reference eliminates this symmetry and reduces the search space dramatically. After solving for offsets, verify that no two persons receive the same seat — a distinctness constraint that is itself an inequality offset_i ≠ offset_j (mod n).

Examiners often combine seating inequalities with “either‑or” statements such as “Either A is second to the left of B or C is third to the right of D”. Treat each branch as a separate sub‑puzzle: impose the first branch’s equalities/inequalities, solve, then impose the second branch, solve, and finally intersect the two solution sets. The intersection yields the statements true in *all* valid arrangements — exactly the “must be true” conclusions. A common trap is to mix constraints from different branches, producing a hybrid arrangement that satisfies neither branch fully.

When the puzzle also contains directional clues like “E faces the centre” (in a circular‑facing‑in/out variant), the facing direction does not affect positional inequalities but may restrict who can be “immediate left” of whom. Encode facing as a binary variable and add the implication “if X faces centre then left‑neighbour is (pos − 1) mod n else left‑neighbour is (pos + 1) mod n”. This conditional can be linearised by creating two parallel offset variables, one for each facing state, and activating the appropriate one with a big‑M style constraint — a technique borrowed from integer programming but easily simulated by hand for the tiny domains in these questions.

Interval Intersection Method for Circular Arrangements
Eight persons A–H sit around a circular table facing the centre. Clues: (1) B sits exactly two seats to the right of A. (2) C sits at most one seat away from D. (3) E sits three seats to the left of F. (4) G and H are not adjacent. Determine which of the following must be true: (i) A and C are opposite each other. (ii) B and F are separated by exactly two seats. (iii) D and G are adjacent.
Fix A at seat 1. From (1), B = (1 + 2) mod 8 = 3. From (3), E = (pos(F) − 3) mod 8 ⇒ pos(F) = (pos(E) + 3) mod 8. Clue (2) gives |pos(C) − pos(D)| ∈ {0,1,7} (since distance ≤1 on a circle of 8). Clue (4) forbids |pos(G) − pos(H)| ∈ {1,7}. Enumerate the 8 possible seats for C (1–8) and derive D from the allowed offsets; for each, enumerate E (1–8) and derive F. Keep only assignments where all eight seats are distinct. The intersection of all valid complete arrangements shows: (i) A (seat 1) and C are opposite (seat 5) in every valid arrangement → must be true. (ii) B (seat 3) and F vary; sometimes distance 2, sometimes not → not mandatory. (iii) D and G adjacency occurs in some but not all arrangements → not mandatory. Hence only statement (i) must be true.
Exam‑Day Strategy
When a circular puzzle appears, immediately fix one person at seat 1 and write all other positions as offsets modulo n. Convert every clue into a simple arithmetic relation on offsets. Use a small table (8 × 8 at most) to cross‑off impossible offset pairs; this visual elimination is faster than mental back‑tracking and makes the “must be true” intersection obvious.

Inequalities Involving Exponential and Logarithmic Comparisons

Advanced reasoning sets occasionally embed exponential or logarithmic relationships disguised as “growth” or “doubling” statements. A clue such as “X doubles every year and after three years exceeds Y” translates to X · 2³ > Y or 8X > Y. Because the base (2) and exponent (3) are constants, the inequality remains linear in the variables after the constant factor is computed. The key is to recognise the constant multiplier and pull it out before any chaining.

Logarithmic clues appear as “the log (base 10) of P is at least 2 more than the log of Q”. Using the property log P − log Q = log(P/Q), the statement becomes log(P/Q) ≥ 2 ⇒ P/Q ≥ 10² ⇒ P ≥ 100 Q. Again the inequality reduces to a linear comparison after exponentiation. Examiners rely on the candidate’s ability to perform this conversion instantly; hesitation here consumes valuable seconds.

When both exponential and logarithmic forms appear in the same set, convert every clue to a linear inequality of the type coefficient · variable (> / ≥ / < / ≤) constant · other variable. Then apply the standard chain‑combination rules: align the middle variable, multiply inequalities by positive constants (preserving direction), and add or subtract as needed. Remember that multiplying by a negative constant would reverse the sign, but all growth factors (2, 10, e) are positive, so direction never flips.

A subtle trap is the “compound growth” phrasing: “A increases by 20 % each period for two periods”. The effective multiplier is (1 + 0.20)² = 1.44, not 1.40. Always compute the exact compound factor before writing the inequality. Similarly, “decreases by 10 % each year for three years” yields a factor of 0.9³ = 0.729. Rounding these factors introduces error; keep them as fractions (144/100, 729/1000) or exact decimals.

Because the variable domain in these questions is usually positive (quantities, populations, amounts), taking logarithms or roots is safe and monotonic. If a variable could be zero or negative, the logarithmic form would be undefined — examiners avoid such ambiguity by stating “positive integers” or “amounts”. When the domain is explicitly positive, you may freely apply log to both sides of an inequality to compare exponents, e.g., 2ˣ > 3ʸ ⇒ x log 2 > y log 3. This linearises the comparison and allows direct chaining with other linear clues.

System of Simultaneous Inequalities with Multiple Variables

Many high‑difficulty sets present a system of three or more inequalities linking four or five variables, such as A + B > C, 2C ≤ D + E, D − A < 5. The goal is often to deduce a specific ordering (e.g., “which variable is the largest?”) or to test a conclusion like “E > B”. The standard approach is to treat the system as a linear feasibility problem and apply interval propagation on each variable.

Begin by isolating each variable where possible. From D − A < 5 we get D < A + 5 and A > D − 5. From A + B > C we have C < A + B. From 2C ≤ D + E we obtain E ≥ 2C − D. Substitute the bounds iteratively: replace C in the third inequality with its upper bound A + B to get E ≥ 2(A + B) − D. Then use D < A + 5 to replace D with its maximum, yielding a lower bound on E purely in terms of A and B: E > 2A + 2B − (A + 5) = A + 2B − 5. If the question asks whether E > B must hold, compare the derived lower bound A + 2B − 5 with B. The inequality A + 2B − 5 > B simplifies to A + B > 5. Since A and B are positive integers (a typical implicit domain), this condition is not guaranteed; a counter‑example with A = 1, B = 1 gives A + B = 2 ≤ 5, making the conclusion false. Hence “E > B” is not a must.

When the system contains both “≥” and “>” signs, preserve the strictness throughout propagation. Adding a strict inequality to a non‑strict one yields a strict result; adding two non‑strict yields non‑strict. This rule mirrors the transitive property of mixed signs discussed earlier and is essential for correct “must be true” determination.

If the system is under‑determined (more variables than independent inequalities), the feasible region is a polyhedron with multiple vertices. The “must be true” conclusions correspond to inequalities that hold at *all* vertices. A practical way to test a candidate conclusion is to attempt to construct a vertex that violates it while satisfying all premises — exactly the reverse‑engineering method. Because the dimension is low (≤ 5), a manual vertex search by setting as many variables as possible to their bounds is feasible within exam time.

Examiners sometimes embed a hidden equality by giving a pair of opposite inequalities, e.g., X ≥ Y and X ≤ Y. Recognise this instantly as X = Y and substitute to reduce the variable count. Missing this reduction inflates the apparent complexity and wastes time.

Inequalities Integrated with Syllogistic Statements

Hybrid questions combine classic categorical syllogisms (“All A are B”, “Some C are not D”) with quantitative inequalities (“the number of A exceeds the number of C by at least 3”). The syllogistic part establishes inclusion/exclusion relationships among sets, while the inequality part imposes cardinality constraints. Solving such hybrids requires a two‑layer model: a Venn diagram for set relations and a system of linear inequalities for the cardinalities of the diagram’s regions.

Start by drawing the minimal Venn diagram that captures all categorical statements. Each distinct region (e.g., A ∩ B ∩ C′, A ∩ B′, etc.) receives a non‑negative integer variable representing its cardinality. Translate every “All”, “Some”, “No” statement into linear equations or inequalities on these region variables. For instance, “All A are B” means the region A ∩ B′ has cardinality 0. “Some C are not D” means the region C ∩ D′ has cardinality ≥ 1.

Next, translate the quantitative clues. “Number of A exceeds number of C by at least 3” becomes Σ(regions in A) − Σ(regions in C) ≥ 3. Because the region variables are shared between the two layers, the resulting system is a set of linear inequalities with non‑negativity and integrality constraints. The feasible integer solutions correspond exactly to the valid scenarios.

To answer “which conclusion must be true?”, test each candidate by adding its negation to the system and checking feasibility. Feasibility of a small integer linear system can be decided by hand using bound propagation: compute the minimum and maximum possible value of each region variable from the inequalities, tightening iteratively until a fixed point is reached. If a variable’s lower bound exceeds its upper bound, the system is infeasible and the tested conclusion is mandatory.

A frequent examiner twist is to give a conclusion that is a categorical statement (e.g., “Some B are D”) rather than a numeric one. Convert the categorical conclusion into its cardinality form (≥ 1 for the relevant region) and apply the same negation‑test. Because the Venn diagram has at most 2ⁿ regions (n = number of terms, usually ≤ 4), the number of region variables stays ≤ 16, making manual propagation realistic.

Remember that “Some” statements are existential (≥ 1) while “All” and “No” are universal (equality to 0 or total inclusion). Mixing existential and universal constraints often forces a unique cardinality for a region, which then cascades through the inequality layer. Spotting such forced values early (e.g., a region must be exactly 2) can solve the entire puzzle in seconds.

  • Treating a modulus clue as a simple directional inequality instead of splitting into two branches.
  • Ignoring modular wrap‑around in circular seating, leading to impossible linear offsets.
  • Rounding compound growth factors instead of using exact fractions, causing wrong inequality direction.
  • Dropping strictness when adding a strict and a non‑strict inequality in a simultaneous system.
  • Failing to convert categorical syllogistic statements into cardinality constraints before mixing with numeric inequalities.
  • Mixing constraints from different branches of an either‑or clue without intersecting the solution sets.
  • Overlooking hidden equalities formed by opposite inequalities, missing a variable reduction opportunity.
